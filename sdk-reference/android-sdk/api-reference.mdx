## Installation

Use the latest standard release from [Maven Central](https://central.sonatype.com/artifact/ai.spatius/avatarkit). Compatibility-suffixed artifacts expose a reduced API and are not a drop-in replacement.

```kotlin title="build.gradle.kts"
dependencies {
    implementation("ai.spatius:avatarkit:<latest-version>")
}
```

<Accordion title="setRenderQuality(quality)">
Update the global rendering quality tier. The change takes effect on the next rendered frame across all active `AvatarView` instances.

```kotlin
fun setRenderQuality(quality: RenderQuality)
```

- Call it after `initialize()`. A call made before `initialize()` is ignored and an error is logged; pass the initial tier as `Configuration.renderQuality` instead.
- Calling `setRenderQuality()` turns automatic adjustment (`setAutoRenderQuality()`) off.
</Accordion>

<Accordion title="setAutoRenderQuality(enabled, options)">
Let the SDK lower the render quality tier when the GPU cannot keep up. Off by default.

```kotlin
fun setAutoRenderQuality(
    enabled: Boolean,
    options: AutoRenderQualityOptions = AutoRenderQualityOptions()
)
```

```kotlin
AvatarSDK.onRenderQualityChanged = { quality, reason ->
    Log.i("Avatar", "Render quality: $quality, $reason")
}
AvatarSDK.setAutoRenderQuality(true, AutoRenderQualityOptions(maxQuality = RenderQuality.HIGH))
```

- The SDK judges the load only from frames rendered while the Avatar is idle; speaking frames depend on the network and are not used. It lowers the tier one step at a time when the GPU render time exceeds `loadThreshold` of the 33.3 ms frame budget (the render loop runs at 30 fps).
- Besides the three tiers, the SDK uses one intermediate step between each pair of tiers. The reported tier is the highest tier not above the current step. `onRenderQualityChanged` is called only when that tier changes, with `RenderQualityChangeReason.AUTO_DOWNGRADE` or `AUTO_UPGRADE`.
- Quality stays between `minQuality` and `maxQuality`; with `allowUpgrade = true` it is raised again when the load drops. A current tier outside that range is moved into it as soon as automatic adjustment is turned on.
- Call it after `initialize()`. A call made before `initialize()`, a `loadThreshold` outside 0.6–1.0, or a `minQuality` above `maxQuality` is ignored and an error is logged.
- `setAutoRenderQuality(false)` and `setRenderQuality()` both turn automatic adjustment off and keep the current tier.

See [AutoRenderQualityOptions](#autorenderqualityoptions) for the options.
</Accordion>

<Accordion title="setRenderResolutionConfig(enabled, config)">
Keep the render buffer height of every `AvatarView`, in physical pixels, within `[minHeight, maxHeight]`. Aspect ratio and the view's layout size are unchanged; the system compositor scales the buffer to fit. The quality tier's render scale still applies on top. Off by default.

```kotlin
fun setRenderResolutionConfig(
    enabled: Boolean,
    config: RenderResolutionConfig = RenderResolutionConfig()
)
```

```kotlin
AvatarSDK.setRenderResolutionConfig(
    enabled = true,
    config = RenderResolutionConfig(minHeight = 1080, maxHeight = 1440),
)
```

- `minHeight`: a view shorter than this renders at `minHeight` and is scaled down. Small views render noticeably sharper, at extra GPU cost.
- `maxHeight`: a view taller than this renders at `maxHeight` and is scaled up, which saves GPU work on high-density screens.
- A bound left `null` is not applied.
- A non-positive bound, or a `minHeight` above `maxHeight`, makes the call ignored: an error is logged and the current setting is kept.
- Takes effect on every live `AvatarView` immediately. Read the current setting from `renderResolutionEnabled` and `renderResolutionConfig`.
</Accordion>

<Accordion title="setRenderResolutionCap(enabled, maxHeight) (deprecated)">
<Warning>
**Deprecated.** Use `setRenderResolutionConfig(enabled, RenderResolutionConfig(maxHeight = maxHeight))` instead. `setRenderResolutionCap()` keeps working and will be removed in the next GA release.
</Warning>

Cap the render buffer height while preserving the view's layout size. A non-positive `maxHeight` makes the call ignored: an error is logged and the current setting is kept.

```kotlin
fun setRenderResolutionCap(enabled: Boolean, maxHeight: Int = 1440)
```

```kotlin
// Replacement
AvatarSDK.setRenderResolutionConfig(true, RenderResolutionConfig(maxHeight = 1080))
```
</Accordion>

<Accordion title="setAudioFormat(sampleRate, opusBitrate, inputAudioFormat, opusUplinkEnabled)">
Changes the audio format of this view without reinitializing the SDK. Only the parameters you pass change; `null` keeps the current value.

```kotlin
fun setAudioFormat(
    sampleRate: Int? = null,
    opusBitrate: Int? = null,
    inputAudioFormat: AudioCodec? = null,
    opusUplinkEnabled: Boolean? = null,
)
```

**Parameters:**
- `sampleRate`: The new sample rate in Hz. Accepted: 8000, 16000, 22050, 24000, 32000, 44100, 48000.
- `opusBitrate`: The new uplink Opus bitrate in bits/sec.
- `inputAudioFormat`: The new codec of the audio you feed into the SDK.
- `opusUplinkEnabled`: Whether the SDK compresses the Direct Mode uplink to Opus.

Any change interrupts the current playback and, in Direct Mode, disconnects. Call `start()` to reconnect; audio you feed after the call is interpreted in the new format. The SDK recreates the `AudioTrack` for the next conversation automatically; no audio-side work is needed. Passing values identical to the current format does nothing.

- Switching `inputAudioFormat` to `AudioCodec.OPUS` sets the sample rate to 48000. Switching back to `AudioCodec.PCM` keeps the current rate unless you pass `sampleRate` in the same call.
- With PCM input at a rate the Opus uplink does not support (anything other than 8000, 16000, 24000, or 48000), the SDK sends raw PCM. Changing back to a supported rate restores the Opus uplink you requested.
- An unsupported `sampleRate`, or a `sampleRate` passed with Opus input, logs an error and leaves the format unchanged. It is not reported through `onError`.
</Accordion>

#### Render over an Avatar Background

Download the optional 16:9 background from Spatius Studio and add it as a drawable resource. In Compose, place the background `Image` and `AvatarView` in the same `Box`. `AvatarView` renders on a transparent surface by default, so the background shows through.

```kotlin
@Composable
fun AvatarStage(
    avatar: Avatar,
    scope: CoroutineScope,
) {
    Box(
        modifier = Modifier
            .fillMaxWidth()
            .aspectRatio(16f / 9f)
            .clipToBounds(),
    ) {
        Image(
            painter = painterResource(R.drawable.avatar_background),
            contentDescription = null,
            contentScale = ContentScale.Crop,
            modifier = Modifier.fillMaxSize(),
        )

        AndroidView(
            factory = { context ->
                AvatarView(context).also { avatarView ->
                    avatarView.init(avatar, scope)
                }
            },
            modifier = Modifier.fillMaxSize(),
        )
    }
}
```

For square or portrait display windows, center this 16:9 stage inside a clipped outer container. See [Avatar Background](/concepts/avatar-background) for the shared cropping rules.

### AudioFormat

Audio format of an `AvatarView`. Pass it to `AvatarView.init(...)` and change it later with `controller.setAudioFormat()`.

```kotlin
class AudioFormat
```

##### Initializers

<Accordion title="AudioFormat(sampleRate:opusBitrate:inputAudioFormat:opusUplinkEnabled:)">
Creates a new audio format.

```kotlin
class AudioFormat(
    sampleRate: Int,
    val opusBitrate: Int = 48000,
    val inputAudioFormat: AudioCodec = AudioCodec.PCM,
    val opusUplinkEnabled: Boolean = true,
)
```

**Parameters:**
- `sampleRate`: The audio sample rate in Hz. Supported sample rates are: 8000, 16000, 22050, 24000, 32000, 44100, 48000. Not used when `inputAudioFormat` is `AudioCodec.OPUS`: Opus always decodes at 48 kHz, so the view runs at 48000.
- `inputAudioFormat`: The codec of the audio you feed into the SDK via `send`. `AudioCodec.PCM` (default) for raw PCM16, `AudioCodec.OPUS` for Opus. Applies to all audio fed to the view until you change it with `controller.setAudioFormat()`; audio that does not match is reported as `AvatarError.InvalidAudioInput`.
- `opusUplinkEnabled`: Whether the SDK compresses the direct mode uplink to Opus. On by default, which reduces the upload to roughly an eighth at the cost of encoding on the client. Set `false` to keep a raw PCM uplink. Not used with Opus input, which is already compressed. With PCM input, `sampleRate` must be 8000, 16000, 24000, or 48000; on any other rate the SDK logs a warning and sends raw PCM instead of failing to initialize.
- `opusBitrate`: Target bitrate in bits/sec for the uplink the SDK encodes. Defaults to 48000. Higher means better quality and a larger upload.
</Accordion>

### AutoRenderQualityOptions

Options for `AvatarSDK.setAutoRenderQuality()`.

```kotlin
data class AutoRenderQualityOptions(
    val minQuality: RenderQuality = RenderQuality.STANDARD,
    val maxQuality: RenderQuality = RenderQuality.ULTRA,
    val allowUpgrade: Boolean = false,
    val loadThreshold: Float = 0.8f,
)
```

| Property | Type | Description |
|----------|------|-------------|
| `minQuality` | `RenderQuality` | Lowest tier the SDK may use. Must not be above `maxQuality`. |
| `maxQuality` | `RenderQuality` | Highest tier the SDK may use. |
| `allowUpgrade` | `Boolean` | Raise the tier again, up to `maxQuality`, once the GPU load drops. |
| `loadThreshold` | `Float` | How busy the GPU must be before the tier is lowered, as a fraction of the 33.3 ms frame budget. Range 0.6 to 1.0. |
