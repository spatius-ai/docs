## Installation

Add the Flutter package from [pub.dev](https://pub.dev/packages/spatius_avatarkit):

```bash
flutter pub add spatius_avatarkit
```

The package supports iOS and Android Flutter apps.

## Import

```dart
import 'package:spatius_avatarkit/spatius_avatarkit.dart';
```

## Initialize

Initialize AvatarKit once before loading avatars or creating an avatar view.

```dart
await AvatarSDK.initialize(
  appID: appId,
  configuration: Configuration(
    drivingServiceMode: DrivingServiceMode.direct,
    logLevel: LogLevel.all,
  ),
);

await AvatarSDK.setSessionToken(sessionToken);
```

Use `DrivingServiceMode.direct` for [Direct Mode](/direct-mode/client).

`initialize` fails fast when `appID` is missing, rather than returning silently. Get an App ID from [app.spatius.ai](https://app.spatius.ai/).

### Configuration

| Field | What it does |
|-------|--------------|
| `region` | Defaults to `'auto'`: the SDK selects the closest serving region at initialization and reuses the cached choice on later launches. Pass `'us-west'`, `'ap-northeast'`, or `'cn-beijing'` to force that region. If automatic selection cannot be reached, the SDK falls back to a default region and continues initializing. |
| `drivingServiceMode` | Use `DrivingServiceMode.direct` for Direct Mode, as described above. |
| `logLevel` | SDK log verbosity. |
| `renderQuality` | Rendering quality tier. Defaults to `RenderQuality.ultra`. |

The audio format is not part of `Configuration`. Set it per view with `AvatarWidget(audioFormat:)`; see [AudioFormat](#audioformat).

### RenderQuality

`RenderQuality.ultra` is the default and highest-quality tier. Use `high` or `standard` only when you intentionally trade visual quality for lower rendering cost.

```dart
enum RenderQuality { standard, high, ultra }

await AvatarSDK.setRenderQuality(RenderQuality.ultra);
```

`setRenderQuality` takes effect on the next rendered frame. Call it after `initialize`: a call made before is ignored and an error is logged natively, on both iOS and Android. Pass the initial tier as `Configuration.renderQuality` instead. Calling `setRenderQuality` turns automatic adjustment off.

### Automatic render quality

`setAutoRenderQuality` lets the SDK lower the render quality one step at a time when the GPU cannot keep up. It is off by default.

```dart
AvatarSDK.onRenderQualityChanged = (quality, reason) {
  debugPrint('Render quality: $quality, $reason');
};

await AvatarSDK.setAutoRenderQuality(
  enabled: true,
  options: const AutoRenderQualityOptions(maxQuality: RenderQuality.high),
);

final enabled = await AvatarSDK.autoRenderQualityEnabled();
```

```dart
const AutoRenderQualityOptions({
  RenderQuality minQuality = RenderQuality.standard,
  RenderQuality maxQuality = RenderQuality.ultra,
  bool allowUpgrade = false,
  double loadThreshold = 0.8,
})
```

| Field | What it does |
|-------|--------------|
| `minQuality` | Lowest tier the SDK may use. Must not be above `maxQuality`. |
| `maxQuality` | Highest tier the SDK may use. |
| `allowUpgrade` | Raise the tier again, up to `maxQuality`, once the GPU load drops. |
| `loadThreshold` | How busy the GPU must be before the tier is lowered, as a fraction of one frame's time budget: 40 ms on iOS, 33.3 ms on Android. Range 0.6 to 1.0. |

- The SDK judges the load only from frames rendered while the Avatar is idle.
- Besides the three tiers, the SDK uses one intermediate step between each pair of tiers. `onRenderQualityChanged` is called only when the reported tier changes, with `RenderQualityChangeReason.autoDowngrade` or `RenderQualityChangeReason.autoUpgrade`. It is not called for `setRenderQuality`.
- A current tier outside `minQuality`–`maxQuality` is moved into that range as soon as automatic adjustment is turned on.
- A call made before `initialize`, a `loadThreshold` outside 0.6–1.0, or a `minQuality` above `maxQuality` is ignored and an error is logged natively.
- `autoRenderQualityEnabled()` returns a `Future<bool>`, unlike the native property of the same name.

### Render resolution

`setRenderResolutionConfig` keeps the render buffer height of every avatar view, in physical pixels, within `[minHeight, maxHeight]`. Aspect ratio and the view's layout size are unchanged; the system scales the buffer to fit, and the quality tier's render scale still applies on top. It is off by default.

```dart
await AvatarSDK.setRenderResolutionConfig(
  enabled: true,
  config: const RenderResolutionConfig(minHeight: 1080, maxHeight: 1440),
);

final enabled = await AvatarSDK.renderResolutionEnabled();
final config = await AvatarSDK.renderResolutionConfig();
```

- `minHeight`: a view shorter than this renders at `minHeight` and is scaled down. Small views render noticeably sharper, at extra GPU cost.
- `maxHeight`: a view taller than this renders at `maxHeight` and is scaled up, which saves GPU work on high-density screens.
- A bound left `null` is not applied.
- A non-positive bound, or a `minHeight` above `maxHeight`, makes the call ignored: an error is logged natively and the current setting is kept.
- `renderResolutionEnabled()` and `renderResolutionConfig()` are methods that return a `Future`, unlike the native properties of the same names.

<Warning>
**Deprecated:** `AvatarSDK.setRenderResolutionCap({required bool enabled, int maxHeight = 1440})`. Use `setRenderResolutionConfig(enabled: enabled, config: RenderResolutionConfig(maxHeight: maxHeight))` instead. It keeps working and will be removed in the next GA release. A non-positive `maxHeight` is ignored and an error is logged.
</Warning>

### AudioFormat

Each avatar view has its own audio format, so two views in one app can run different sample rates. Pass it to `AvatarWidget(audioFormat:)` when you create the view; it defaults to 16 kHz PCM. The value is used when the native view is created, so changing the widget property afterwards has no effect. Use `AvatarController.setAudioFormat` to change it at runtime.

```dart
const AudioFormat({
  int sampleRate = 16000,
  AudioCodec inputAudioFormat = AudioCodec.pcm,
  bool opusUplinkEnabled = true,
  int opusBitrate = 48000,
})
```

| Field | What it does |
|-------|--------------|
| `sampleRate` | Sample rate in Hz. Supported: 8000, 16000, 22050, 24000, 32000, 44100, 48000. Not used when `inputAudioFormat` is `AudioCodec.opus`: Opus always decodes at 48 kHz, so the session runs at 48000. |
| `inputAudioFormat` | The codec of the audio you feed into the SDK via `send`. `AudioCodec.pcm` (default) for raw PCM16, `AudioCodec.opus` for Opus. Change it on a live view with `setAudioFormat`. |
| `opusUplinkEnabled` | Whether the SDK compresses the Direct Mode uplink to Opus. On by default, which reduces the upload to roughly an eighth at the cost of encoding on the client. Set `false` to keep a raw PCM uplink. Not used with Opus input, which is already compressed. With PCM input, `sampleRate` must be 8000, 16000, 24000, or 48000; on any other rate the SDK logs a warning and sends raw PCM instead of failing. |
| `opusBitrate` | Target bitrate in bits/sec for the uplink the SDK encodes. Defaults to 48000. Higher means better quality and a larger upload. |

Audio that does not match the declared `inputAudioFormat` is reported through `AvatarController.onError` as `AvatarError.invalidAudioInput`.

`AudioFormat` has value equality and converts with `toJson()` / `AudioFormat.fromJson()`.

### Change the audio format at runtime

Read the format in effect for a view with `controller.audioFormat()`. It returns the format after the SDK's normalization, for example 48000 Hz for Opus input.

```dart
final format = await controller.audioFormat();

await controller.setAudioFormat(sampleRate: 24000);
await controller.start(); // Direct Mode: reconnect, then send audio in the new format.
```

`setAudioFormat({sampleRate, inputAudioFormat, opusBitrate, opusUplinkEnabled})` changes the format of a live view without tearing the SDK down. Every parameter is optional; `null` keeps the current value.

- Any change interrupts whatever is playing and, in Direct Mode, disconnects. Call `start()` again and feed audio in the new format.
- Switching `inputAudioFormat` to `AudioCodec.opus` pins the sample rate at 48000. Switching back to `AudioCodec.pcm` keeps the current rate unless you pass `sampleRate` in the same call.
- Accepted sample rates are 8000, 16000, 22050, 24000, 32000, 44100, and 48000. An unsupported rate, or a `sampleRate` paired with Opus input, is logged by the SDK and leaves the format unchanged.

## Load an avatar

```dart
final avatar = await AvatarManager.shared.load(
  id: avatarId,
  onProgress: (progress) {
    // Update loading UI.
  },
);
```

To create an Avatar from a local asset path instead, use `derive`. A known SDK error raised during `load` or `derive` is thrown as a Flutter `AvatarError` value; any other failure is thrown as a `PlatformException`. `derive` throws `AvatarError.avatarAssetMissing` on both iOS and Android when the asset is missing.

```dart
try {
  final avatar = await AvatarManager.shared.derive(assetPath);
} on AvatarError catch (error) {
  // For example, AvatarError.avatarAssetMissing.
}
```

## Render and control playback

The Flutter view creates an `AvatarController` when the platform view is ready. Keep that controller and use it for lifecycle, state, and audio operations.

```dart
void onAvatarViewCreated(AvatarController controller) {
  controller.onConnectionState = (state, errorMessage) {
    // Observe Direct Mode connection state.
  };

  controller.onConversationState = (state) {
    // Observe avatar playback state.
  };

  controller.onError = (error) {
    // Log or surface AvatarError.
  };
}
```

`AvatarError` is an enum, so a `switch` over it without a `default` case must list every value. `AvatarError.renderBlankCanvas` is reported through `onError` when the view reported its first frame, but one second later nothing visible had been drawn. It is reported at most once per view; an Avatar moved entirely out of the view or scaled to nothing by its transform is reported the same way.

### Render over an Avatar Background

Download the optional 16:9 background from Spatius Studio, add it to your Flutter assets, and declare it in `pubspec.yaml`.

```yaml
flutter:
  assets:
    - assets/avatar-background.webp
```

Place the background and `AvatarWidget` in the same `Stack`, with the image first.

```dart
AspectRatio(
  aspectRatio: 16 / 9,
  child: ClipRect(
    child: Stack(
      fit: StackFit.expand,
      children: [
        Image.asset(
          'assets/avatar-background.webp',
          fit: BoxFit.cover,
        ),
        AvatarWidget(
          avatar: avatar,
          audioFormat: const AudioFormat(sampleRate: 16000),
          onPlatformViewCreated: onAvatarViewCreated,
        ),
      ],
    ),
  ),
)
```

For square or portrait display windows, center this 16:9 stage inside a clipped outer widget. See [Avatar Background](/concepts/avatar-background) for the shared cropping rules.

For Direct Mode audio input, start the connection and send PCM chunks:

```dart
await controller.start();
controller.send(audioBytes, end: isLastChunk);
```

For audio source and timing guidance, see [Audio](/concepts/audio).
